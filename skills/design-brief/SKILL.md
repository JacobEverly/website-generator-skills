Generate a structured design system (DESIGN.md) for a new website project. This is the **only human checkpoint** in the website building pipeline — everything after DESIGN.md approval runs autonomously.

## Two-Layer Architecture

Every Boundless site uses a two-layer design system:
1. **Base theme** (`~/.claude/design-library/boundless-base.md`) — shared aesthetic, immutable rules, component defaults
2. **Project DESIGN.md** (project root) — extends base with project-specific personality: accent colors, display fonts, motion style, unique components

Read the base theme first: `~/.claude/design-library/boundless-base.md`

## Mode: Interactive (default)

### Step 1: Always Ask First

**"Who is the target user?"** — this shapes the entire design system. Ask this before anything else.

Then gather:
- **Vibe/mood**: What should this feel like? (3-5 adjectives)
- **Business goal**: What's the single most important action a visitor should take?
- **References**: Any sites they admire? Search the inspiration library for matches.
- **Anti-references**: What should this explicitly NOT look like?
- **Constraints**: Dark mode? Specific brand colors? Must-include elements?

Use the `AskUserQuestion` tool. Do not proceed without answers.

### Step 2: Search the Inspiration Library

Search `~/.claude/design-library/LIBRARY.md` and `~/.claude/design-library/inspirations/` for relevant references based on the user's vibe words and references.

If matches exist, read them and incorporate their patterns into the design system.

### Step 3: Generate the Design Brief

Create a brief markdown file at `{project-dir}/design-brief.md`:

```markdown
# Design Brief

## Target User
{who they are, their context, what they care about}

## Business Goal
{the single most important conversion/action}

## Vibe
{3-5 adjectives + elaboration}

## References
{sites/inspirations that inform this, with what specifically to take from each}

## Anti-References
{what to avoid, with specifics}

## Constraints
{technical or brand constraints}
```

### Step 4: Generate DESIGN.md

Create `{project-dir}/DESIGN.md` that extends the base theme:

```markdown
# DESIGN.md

> Extends [Boundless Base Theme](~/.claude/design-library/boundless-base.md)
> Generated by /design-brief on {date}

## Project Identity

**Name**: {project name}
**Tagline**: {one-line description}
**Audience**: {target user, one sentence}
**Goal**: {primary conversion action}

## Personality Layer

What makes THIS site different from the base theme:

### Display Font
{chosen display font + why it fits the personality}
- Where to use: {hero headings, section titles, etc.}
- Where NOT to use: {body, metadata, nav}

### Accent Palette
{1-2 accent colors derived from brand/imagery, NOT for chrome}
```css
--accent-primary: {color};    /* {where to use} */
--accent-secondary: {color};  /* {where to use, if needed} */
```

### Motion Style
{subtle/moderate/bold — with specific guidance}
- Page load: {entrance animation approach}
- Hover effects: {what interactive surfaces do}
- Scroll: {parallax? reveal? none?}
- Timing: {fast 150ms? medium 300ms? slow 500ms?}

### Unique Components
{any components that deviate from the base theme, with specifics}

## Section Plan
{ordered list of page sections, max 10}
1. {section name} — {purpose, ~one sentence}
2. ...

## Image Direction
{style guidance for any generated or sourced images}
- Hero: {what it should show/feel like}
- Section images: {approach}
- Icons: {custom? line? solid? none?}

## Copy Voice
{how the writing should sound — not the full copy, just the voice}
- Headlines: {punchy? descriptive? provocative?}
- Body: {technical? accessible? both?}
- CTAs: {action-oriented wording style}

## Hard Rules (from base + project-specific)
{list of immutable design rules — base theme "Never Do" list plus any project additions}
```

### Step 5: Persist to CLAUDE.md

Run the `teach-impeccable` skill internally to save key design context to the project's CLAUDE.md so all future sessions in this project have the design system loaded.

### Step 6: Present for Approval

Show the user:
1. A summary of the design direction (3-4 sentences)
2. The key differentiators from base theme
3. The section plan
4. Ask: **"Does this design direction feel right? Once approved, generation runs autonomously."**

Do NOT proceed to generation until the user explicitly approves.

## Mode: From URL (`--from-url`)

When `from-url` is provided, extract a design system from an existing live site:

1. Use Playwright to navigate to the URL and capture screenshots + DOM
2. Analyze the complete visual language (colors, typography, spacing, components, motion)
3. Generate a DESIGN.md that codifies what the site is doing
4. Ask the user what to keep, modify, or discard
5. Generate the final DESIGN.md incorporating their feedback

This is useful for:
- Rebuilding an existing site with the same design language
- Using a reference site as a starting point and customizing from there

---

## Quality Checklist

Before presenting DESIGN.md for approval:
- [ ] Display font chosen is distinctive (not Inter for display — Inter is body only in base theme)
- [ ] Accent colors are specific hex values, not vague descriptions
- [ ] Motion style is concrete (timing, easing, what animates)
- [ ] Section plan has ≤10 sections
- [ ] No violations of base theme "Never Do" list
- [ ] Copy voice guidance is specific enough to write from
- [ ] Image direction is actionable
